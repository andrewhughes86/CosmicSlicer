# CosmicSlicer — instructions for agents

CosmicSlicer is a slicer for FFF 3D printers: a Rust rebuild of OrcaSlicer (egui + wgpu), in
the Cosmic family's look (CosmicDMS, CosmicCut). OrcaSlicer is AGPL-3.0; CosmicSlicer uses its
option definitions, settings layout and icons, so CosmicSlicer is AGPL-3.0-or-later too.

## The first rule: never crash
OrcaSlicer's crashes are the reason this exists.
- No `unwrap`, `expect`, `panic!`, `unreachable!`, `todo!` or `unsafe` in non-test code (the
  workspace lints deny them). Input-derived numbers are hostile: `get()` not `[i]`, finite
  checks, caps on sizes and counts (see `model::stl`, `state::Session::bed`).
- `f32::clamp` / `f64::clamp` / `Ord::clamp` panic when the bounds cross or are NaN: only
  clamp with bounds that cannot cross; with computed bounds, use `min` / `max` (see the
  layer slider and the title bar for the two times this bit).
- egui asserts on some layout misuse (e.g. `add_space` inside a `Grid`). Every page, dialog,
  settings page and canvas tool is drawn headlessly by `app::smoke` tests; add new UI there.
- `CosmicSlicerApp::ui` catches a panic in a frame, closes dialogs and keeps the project.
  That is a last resort, not an error path: fix the bug. Every panic also writes a report to
  `<data>/crashes/` (`recovery::install_crash_reports`).
- Work is never lost: `recovery::Autosaver` saves the session a minute after each change and
  before slicing, holding an OS file lock while the app runs; a free lock at start-up means a
  crashed session, whose project is offered back. Files the app writes go through
  `store::write_atomic` (temp file, sync, rename) and damaged JSON is set aside, not fatal.
- Data folder: `store::data_dir()` (`COSMICSLICER_DATA_DIR` overrides it). Screenshot runs write
  nothing there unless that variable points them at a scratch folder.

## Layout
- `crates/config` — OrcaSlicer's option definitions and Tab layout
  (`assets/settings/orca_settings.json`, generated by `tools/extract_orca_settings.py` from
  OrcaSlicer's `PrintConfig.cpp` and `Tab.cpp`), values, presets. Values are stored as
  OrcaSlicer serialises them (vectors comma-separated, bools `1`/`0`).
- `crates/config` also holds `library` (OrcaSlicer's profile library, packed into
  `assets/profiles/orca_profiles.bin` by `tools/pack_orca_profiles.py`; vendors unpacked on
  first use; `inherits` then `include` then own values), `expr` (the custom G-code macro
  language and `compatible_printers_condition`), `userfiles` (user presets as OrcaSlicer-style
  JSON diffs). Custom G-code that cannot be evaluated fails the slice — never pass template text
  to a printer. The engine test `every_library_printer_renders_its_gcode` renders every
  printer's templates; keep it at zero failures when changing either.
- The engine's G-code is a program of `gcode::Op`s first: `motion::plan` times it as the
  firmware will (trapezoids, look-ahead, axis limits, jerk or junction deviation), then it is
  rendered with M73 progress. `gcodeview` reads any G-code back into the same Preview and
  estimate; the engine tests check that our own G-code reads back with the same time and
  filament. Travel inside an island uses `travel::Region` (no retraction needed inside;
  routed round walls with "Avoid crossing walls").
- Walls: `walls` makes the loops; narrow parts and gaps go through `medial` (centre lines with
  widths, split into constant-width `Path`s). `overhang` marks each wall segment's overhang
  degree in `Path::overhang` (kept through `Path::rotate` / `Path::reverse`); the G-code writer
  splits loops into runs by degree for speed, fan, flow and the Overhang wall type, and builds
  scarf seams there. `plan` runs in two passes so solid infill can see the sparse infill below
  (internal bridges).
- `crates/model` — meshes, objects, plates, primitives; `arrange` (no-fit-polygon nesting of
  convex footprints) and `orient` (auto orient); objects with the same non-zero `shared` are
  instances of one object (`state::Session::sync_instances` carries edits across each
  frame); `load` (every format, zip archives); `threemf` reads and writes 3MF projects in
  OrcaSlicer's layout (objects and parts in `3D/Objects/`, `Metadata/model_settings.config`,
  `project_settings.config`, painted facets kept as Orca's encoded strings).
- `crates/connect` — printer connections: OrcaSlicer's print hosts over HTTP (`hosts`, on a
  small blocking `http` client), Bambu Lab LAN mode (`bambu`: MQTT, FTPS, sliced 3MF, SSDP,
  camera), and `link`, a worker thread per printer. Every read and write has a timeout; the
  UI only sends requests and picks up events (`ui-egui/src/devices.rs`), never waits.
- `crates/import` — the model readers (mesh formats and STEP/IGES/SAT with their B-rep kernel),
  vendored from CosmicDMS; keep fixes in step with it.
- `crates/engine` — the slicer (`calib`: the calibration prints' per-layer changes and the drawn
  pressure advance tests): `slicing` (mesh → layer shapes), `walls`, `plan` (top /
  bottom / solid / sparse regions per island), `infill`, `skirt`, `support`, `gcode` (order,
  travel, cooling, G-code, estimates, Preview moves). `geom` wraps `clipper` (Orca's Clipper, ported) under
  `catch_unwind`; `settings` clamps every value it reads. `slice()` never panics.
  `SLICE_FILE=x.stl cargo test --release -p CosmicSlicer-engine slice_a_file -- --nocapture`
  times a real model. `tools/parity.sh <dir> [x1c mk4 voron]` slices a reference set with
  OrcaSlicer's command line (presets flattened by `tools/parity_flatten.py`, since Orca's CLI
  ignores `inherits`) and with ours using the settings Orca wrote into its G-code, then
  `parity_tests` compares them (time, filament, features, retractions, toolpath maps and
  layer pictures in `<dir>/<model>@<set>/`). `tools/parity_diff.py <case> [--layer N] [--feature F]`
  compares the two files line by line; `PARITY.md` lists every known difference and why. `clipper`, `slicing`, `seam`,
  `connect` and `arcs` are ports of Orca's SeamPlacer, connect_infill and ArcFitter down to libstdc++'s
  random numbers and sort, so keep them so. Orca's behaviour is the reference: when they
  differ, read Orca's source for the rule rather than guessing, and never imitate a tie-break: its
  ties turn on nanometres, so port the arithmetic (`PARITY.md`).
- `crates/ui-egui` — the UI. `project.rs` maps the session to and from 3MF projects (presets by name, edits kept);
  `slicer.rs` runs the engine on a thread (results checked against a
  settings fingerprint and the model revision); `preview.rs` colours toolpaths. `state.rs` is the session (all edits go through its methods, which
  checkpoint undo); `topbar`, `sidebar`, `settings`, `pages`, `dialogs`, `menus`; `viewport/`
  is the 3D canvas (wgpu renderer, camera, gizmos, overlays).
- `apps/CosmicSlicer` — the binary and its command-line automation.

## Conventions
- Colours only from `theme::Tokens` (the Cosmic palettes); containers from `ui_kit`.
- Icons are OrcaSlicer's SVGs in `assets/icons/orca/`, recoloured into the theme by
  `icons::colourise` (teal → accent, greys → ink); CosmicSlicer's own art goes in
  `assets/icons/cosmic/` and wins over a same-named Orca icon.
- Units inside are millimetres and degrees, as in OrcaSlicer.
- Regenerate the profile pack with
  `python3 tools/pack_orca_profiles.py <OrcaSlicer>/resources/profiles assets/profiles/orca_profiles.bin`.
- Regenerate the calibration models with
  `python3 tools/pack_calib_models.py <OrcaSlicer>/resources/calib assets/calib` (needs DracoPy).
- Regenerate the translations with
  `python3 tools/pack_translations.py <dir of OrcaSlicer_<lang>.po files> assets/i18n/translations.bin`
  (run it again when UI texts change, so new texts that Orca has are kept). Show text through
  `i18n::tr` where it is OrcaSlicer's wording; keyboard shortcuts live in `shortcuts::ALL`.
- Regenerate the settings JSON with
  `python3 tools/extract_orca_settings.py <OrcaSlicer>/src assets/settings/orca_settings.json`.

## Before finishing
`cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo test --workspace`. On a developer's machine run cargo through `tools/capped.sh`
(e.g. `tools/capped.sh cargo test -j 1 -p CosmicSlicer-import`): it runs in its own
memory-capped systemd scope (`CAP`, default 2G), so a runaway test is killed instead of the
editor, and logs output and memory to `target/diag/`. The model readers' fuzz test
(`import::fuzz`, also used by `engine::fuzz_tests` and the 3MF tests) leaves a case's input
in `<tmp>/cosmicslicer-fuzz/` while it runs, so an out-of-memory kill names its culprit;
cases over a second are printed and saved as `<tmp>/cosmicslicer-fuzz-slow-*.bin`. Replay a
model file with `COSMICSLICER_FUZZ_REPLAY=<file>` (test `import::fuzz_tests::replay`: time,
triangles, volume, open edges). CI (`.github/workflows/ci.yml`) runs the same on Linux, Windows and
macOS, plus the real app on a software GPU (slice, export, crash, restore, panic report). Check UI changes with screenshot runs, which save nothing:
`cargo run -- --add Cube --tab preview --screenshot out.png` (see `--help`).
